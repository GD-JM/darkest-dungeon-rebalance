## 동작

공통 명령의 Git push 성공 → main SHA 확인 → 별도 소스 확보 → 원문 의도와 실제 diff 검사 → Codex JSON 문안 작성 → 기존 빌드/주석 검사 → 영웅 비교 이미지 생성 → Steam UGC 전송 → 설명·이미지 목록·배포 체크포인트 재조회.

- Steam에 로그인된 현재 Windows 사용자로 실행합니다. Chrome 로그인·브라우저 쿠키는 사용하지 않습니다. Steam이 꺼져 게시에 실패하면 실행한 push의 성공 여부와 배포 실패를 따로 기록합니다. 준비된 뒤 같은 공통 명령으로 재시도합니다.
- 원문 기록은 [공통 계약](agent-contract.md)을 통해 Claude와 Codex가 작업 중 남깁니다. 자동화는 관련 없는 개인 대화 전체를 수집하지 않습니다.
- 문안은 기존 ChatGPT 로그인으로 Codex CLI를 실행해 생성하므로 계정 사용량을 소비합니다. 한 SHA의 실패한 모델 호출은 최대2회입니다. 명확한 근거 누락/모순 결과는 재호출을 반복하지 않습니다.
- 업데이트 노트는 마지막 배포 대비 영어+중국어 간체, 설명은 기존10개 언어, 영웅 이미지는 바닐라 대비 누적 차이입니다.
- 기본 이미지 너비1200·최대높이1500. 길면 기술 블록 경계에서2장으로 나눕니다. 글자 축소·내용 삭제로 억지로 맞추지 않습니다.
- 생성물은 `runtime/jobs/<SHA>/`에 원문 입력·모델 결과·빌드·이미지·해시·게시 이력과 함께 보존합니다. 저장소에 생성 커밋을 되밀어 무한 push를 일으키지 않습니다.

## 공통 푸시와 재시도

Claude/Codex에서 “푸시해”라고 요청하면 [공통 계약](agent-contract.md)의 명령을 사용합니다. 실제 커밋은 먼저 만들고, 푸시는 다음처럼 별도로 실행합니다.

```powershell
& 'C:/Users/lemm1/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B 'C:/Users/lemm1/Documents/Codex/2026-10-04/new-chat-2/workshop-sync/push.py' --repo '<실제 체크아웃 절대 경로>' --branch main
```

`--branch test`는 GitHub만 갱신합니다. main은 캡처한 정확한 SHA를 push한 뒤 배포를 수행하고 결과를 출력합니다. 실패 후 같은 명령을 반복하면 up-to-date push도 미완료 배포를 재시도합니다. 완료된 SHA는 노트/이미지를 중복 게시하지 않습니다. 원격 main이 그 사이 달라지면 다른 커밋을 몰래 게시하지 않고 중단합니다.

일반 `git push`, GitHub Desktop의 push, 다른 PC의 push는 자동 배포하지 않습니다. 이 프로그램은 시스템의 모든 Git 호출을 가로채지 않습니다. 공통 명령을 사용해야 합니다. `start.ps1`/`install-startup.ps1`은 주기 감시 재설치를 방지하도록 비활성화했습니다.

진단은 `python -B sync.py inspect`, 상태는 `python -B sync.py status`로 확인합니다. 직접 복구용 `once --publish`는 준비된 원격 main을 처리하므로 대상 SHA와 상태를 확인한 운영 작업에서만 사용합니다.

## 상태와 오류

- `runtime/events/*.json`: 공통 명령마다 SHA·Git push 성공·배포 결과·오류를 기록한 영수증.
- `runtime/health.json`: 최근 공통 명령의 실행 결과. 주기 갱신하지 않습니다.
- `runtime/state.json`: 마지막 배포 커밋, 마지막 관찰 커밋, 처리 중인 커밋.
- `runtime/worker.log`: 오류 상세.
- 각 job의 `release.json`: 검토 가능한 문안·이미지·파일 해시.
- `publish-state.json`: 완료 단계. 전송 응답이 유실되면 Steam 메타데이터와 대조하며, 확인 불가능한 경우 중복 노트를 올리지 않고 멈춥니다.

의도 누락 시 실제 사용자 원문과 이번 변경 경로를 `design/workshop/intents/*.json`에 추가하고 push합니다. 아직 게시 중인 커밋이 있으면 그 배포를 먼저 정리합니다. 원격 기록 강제 변경, 인증 만료, Steam 약관 동의 요구는 자동 우회하지 않습니다.

## 검증 범위

단위 검증은 분할 행 보존·글자 경계·파일 크기, 의도 누락 차단, 중복 submit 방지, 응답 유실 복구, 외부 쓰기 없는 dry-run을 다룹니다. 실제 게임 플레이 검증을 대신하지 않습니다. Steam 제출 성공/메타데이터 조회는 API 수신 확인이며 다운로드된 게임의 동작까지 입증하지 않습니다.

기존 main 빌드에서 `duelist|disengage`의 why 문구 누락 경고가 발견되었습니다. 이번 이미지 분할은 기존 승인 수치와 문구를 유지하며, 자동화가 해당 의도를 임의로 만들어 넣지 않습니다.
