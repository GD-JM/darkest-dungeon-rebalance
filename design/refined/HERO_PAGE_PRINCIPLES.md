## 2. 설명란 구성 (위에서 아래로)

1. 간판 이미지(`title.png`)
2. `[h1]Darkest Refined No.0N · <영웅>[/h1]`
3. **개괄**(3절): 기술 이미지로 들어가기 전에 영웅 전체의 방향을 글로 잡는다.
4. `[h1]바뀐 기술[/h1]`
5. 기술마다 `[h2]<기술명> · <핵심 변화 한 구절>[/h2]` 한 줄, 그 아래 기술 시트 이미지.
6. `[h1]그대로인 것[/h1]`: 있을 때만, 1~2문장.
7. `[h1]이렇게 쓴다[/h1]`: 예시마다 `[h2]` 한 줄과 운용 예시 이미지(8절). 운용이 바닐라와 같으면 이 섹션을 통째로 뺀다.
8. `[h1]설치 · 호환[/h1]`: 필요한 DLC, 이 영웅 파일만 바꾼다는 안내, 합본·다른 같은 영웅 모드와 함께 켜지 말라는 안내.
9. 그림 출처 한 줄: `[i]그림: … © Red Hook Studios. 비공식 팬 모드입니다.[/i]`
10. **맨 밑**: `[h1]다른 영웅 보기[/h1]`.
    - 출시된 영웅만 링크로 건다. 지금 보는 영웅은 굵게, 링크 없이 둔다.
    - 그 아래에 `준비 중:` 목록을 둔다(링크 없음).
    - 업로드 때 자동으로 붙인다. 출시 목록 한 곳만 고치면 모든 페이지에 반영된다.

**갤러리는 표지 한 장만 둔다.** 설명에 쓴 이미지와 옛 리밸런스 비교 카드는 갤러리에 넣지 않는다.

## 3. 개괄 (설명 첫머리)

- 기술 하나하나가 아니라 **영웅 전체 맥락**으로 쓴다. 소개 몇 줄 뒤 곧바로 기술로 들어가면 답답하다.
- 담을 것:
  - 이 영웅이 어떤 영웅인지(정체성)
  - 바닐라에서 전체적으로 무엇이 어긋나 있었는지
  - 이 판에서 영웅 전체가 어떻게 바뀌는지(방향 2~3가지, 필요하면 `[list]`와 `[b]` 머리말)
  - 전체적으로 상향인지 하향인지
- 고정 양식처럼 칸을 채우지 않는다. 그 영웅에게 필요한 것만 고른다. 본문 기준 약 400~900바이트.

## 4. 이미지 사이 글 (`[h2]` 한 줄)

- 스팀 본문 글씨(14px)는 이미지 속 글씨보다 작아 어울리지 않는다. 이미지 사이에는 18px인 `[h2]` 한 줄만 둔다.
- 형식: `<기술명> · <무엇이 바뀌었는지 구체적인 한 구절>`. 40자 이내, 마침표 없음.
  - 예: `관통탄 · 1~4열 어디든 방어 25~50% 관통`
- 시트와 겹치는 설명(목록, 문단)은 본문에 쓰지 않는다. 시트의 '왜 바꿨나' 문장을 그대로 옮기지 않는다. 멋 부린 표어를 쓰지 않는다.
- 지우는 본문 문장에 시트에 없는 사실이 있으면 먼저 시트의 변경 의도나 note로 옮긴다.

## 5. 기술 시트 구성 (이미지)

위에서 아래로:

1. 머리: 아이콘, 공식 기술명, 배지(REWORKED 등), 부제(`영어명 · 원래 이름 · 한 구절`)
2. **바뀐 점**: 바닐라 → 현재. 명중·치명·확률은 1레벨, 효과 크기는 1~5레벨 수열로 적는다.
3. 레벨별 표(필요할 때), note
4. **왜 바꿨나**: 두괄식 한두 문장(50~90자, 120자 이하). 바닐라의 문제와 바꾼 결과를 결론부터 쓴다. 굵은 글씨에 금색 세로줄.
5. **공식 원문**(있을 때만, 7절): 원문과 `출처 · …`
6. **변경 의도**: 자세한 이유(6절). 문단 2~4개.
7. **비교**: 비슷한 기술 표. 다른 영웅 값은 **현재 빌드 값**이다.
8. **설계 기록**: 의미 있는 변경만(9절).

'기획 의도'라는 이름은 쓰지 않는다. 시트에는 '왜 바꿨나'와 '변경 의도'가 따로 있다.
꾸밈용 강조 상자(box)는 넣지 않는다. 시트에 없는 구체적인 운용 요령이 있을 때만 쓴다.

## 6. 변경 의도 쓰는 법 (가장 중요)

**직관과 개연성을 먼저 적는다(P-30).** 이 리밸런스는 모든 변경이 기술 이름·동작·외형·설정과 효과가 말이 되게 맞물리도록 만들었다. 그래야 제작자도 플레이어도 변경에 납득한다. 변경 의도 첫머리에 그 연결을 한두 문장으로 쓰고, 수치 근거는 그 뒤에 쓴다.

예:

| 기술 | 연결 |
|---|---|
| 고통 | 동료의 출혈·중독을 대신 가져간다 → 그 동료의 고통이 줄어 스트레스가 회복된다 |
| 저격 | 이름이 저격이다 → 호위를 뚫고 노린 적에게 닿는다(보호 무시) |
| 연막탄 | 적에게 연막을 씌운다 → 적 명중이 떨어진다 |
| 엄호 연막 | 아군을 연기로 가린다 → 맞히기 어려우니 아군 회피가 오른다 |
| 사냥개 돌진 | 개가 무는 게 무기로 때리는 것보다 세면 안 된다 → 약하다 |
| 부츠 | 이펙트와 타격음이 강한데 피해를 낮췄다 → 그에 걸맞게 2칸 밀친다 |

- **근거 순서:**
  1. 기록에 있는 연결: `design/changes/<영웅>.md`, `design/workshop/intents/*.json`, `why.json`, 데이터 `//` 주석
  2. 누구나 바로 납득할 만큼 분명한 연결
- **조금이라도 애매하면 연결하지 않는다.** 이름에서 해석을 한 번 더 거쳐야 하는 연결은 빼고, 수치 근거만 쓴다.
- 기록에 없는 새 의도, 사연, 감정을 지어내지 않는다.
- **이력 이야기를 쓰지 않는다.** "처음엔 ~였다가", "넣었다가 뺐다", "한때", 날짜와 경과는 모두 설계 기록에만 둔다. 변경 의도에는 **바닐라 대비 왜 지금 수치·형태인지**만 담백하게 쓴다.
  - 지금 수치의 근거, 비교 대상, 다른 기술·영웅과의 역할 분담, 장신구와의 관계를 쓴다.
- 영웅 전체 방향 같은 제작자의 상위 의도는 개괄과 해당 기술 의도에 쓴다.
  - 예: 방패 파괴자 "도망자 이후 적 대열을 흔드는 기술이 더 필요해졌고, 무희인 방패 파괴자가 그 몫을 가장 많이 맡는다"

## 7. 공식 원문 인용

- 게임 공식 문구는 그 변경의 근거가 된 부분만 골라 출처와 함께 인용한다. 설정을 통째로 붙이지 않는다.
- **원문이 그 효과를 직접 말할 때만** 인용한다.
  - 해석을 한 번 거쳐야 이어지는 문구는 인용하지 않는다(예: '각종 특수탄' → 방어 관통).
  - 우리 설정과 어긋나는 문구는 인용하지 않는다(예: 총사 예복이 '매우 튼튼'인데 체력을 낮춘 경우).
  - 애매하면 뺀다. 빈자리를 다른 인용으로 채우지 않는다.
- 원문은 게임 파일 문구 **그대로** 쓴다.
  - 확인 도구: `lore_lookup.py <영웅id> [검색어]`. 바닐라 한국어 문자열은 `loc.json`에 있다.
  - 잘라 쓸 때는 앞뒤를 `…`로 표시한다. 한 인용은 120자 이내.
- 출처 표기: `길드 설명`, `대장간 설명`, `생존주의자 천막 설명`, `DLC 소개`, `영웅 대사 · 치명타`, `장신구 설명` 등.
- 시트마다 0~2개, 영웅 전체 0~5개. 없어도 된다.
- 인용할 수 있는 것은 게임 안 문구뿐이다. 코믹스, 위키, 제작자 말은 인용하지 않는다.
- **제작자 원문은 플레이어용 글·이미지 어디에도 넣지 않는다.**
  - "제작자 요청으로/지시로" 같은 표현도 쓰지 않는다.
  - 설계자 본인이 쓴 말투로 쓴다. 원문은 내부 기록(changes·intents)에만 둔다.

## 8. '이렇게 쓴다' 운용 예시

- 변경에 납득하지 못한 사람은 새 활용법을 찾아보기를 꺼린다. 그래서 바뀐 영웅을 어떻게 쓰는지 쉽게 풀어 보여 준다. 너무 자세하게 쓰지 않는다.
- **바닐라와 달라진 운영이 가장 돋보이는 대표 예시 1~2개만** 넣는다. 많으면 오히려 별로다.
- **바닐라와 같은 운영은 넣지 않는다.** 운용이 원작과 사실상 같으면 예시를 하나도 넣지 않는다.
- 제목이나 첫 단계에서 "바닐라에서는 못 하던 무엇"이 바로 보이게 쓴다.
- 이미지 한 장(`play_N.png`)에 다음을 담는다.
  - 제목 한 줄
  - 대열 얼굴 4칸: 왼쪽이 4열, 이 영웅은 금테. 각 칸에 열과 역할(8자 안팎)
  - 단계 2~3개(한 줄 60자 안팎, 한다체)
- 동료의 기술과 수치도 **현재 빌드** 기준이다.

## 10. 문체

- `jaemin-output-style` 스킬(`~/.claude/skills/jaemin-output-style`)을 따른다.
  - 어디에나 붙일 수 있는 도입·칭찬을 쓰지 않는다. 근거 없는 의도·감정을 지어내지 않는다.

  - 문장 속 줄표(—, ―)를 쓰지 않는다. 제목의 `—`와 부제의 가운뎃점(·)은 괜찮다.
  - "A가 아니라 B다", "A는 거들 뿐, B가 본업이다" 같은 대구 결론을 쓰지 않는다.
  - 셋씩 늘어놓는 리듬, 감탄, 독자에게 말 걸기(설치 안내의 "~하세요"는 괜찮음), 과장 꾸밈말을 쓰지 않는다.
  - "속도: …" 같은 쌍점 머리말을 쓰지 않는다.
  - 추상적인 평가보다 숫자와 실제 전투 장면을 쓴다.
  - 높임 수준: 시트는 한다체, 설명 본문은 합니다체.
- 내부 코드(P-, G-, R-, SB-0xx, DUE-0xx 등)는 쓰지 않는다. 처음 보는 사람이 읽는 자연어로 쓴다.
- 기술·영웅·장신구 이름은 **게임 공식 한국어 이름**을 쓴다(LANG-001). 모드가 바꾼 이름은 `(원래 …)`로 적는다.
- 명중·치명 보정·효과 확률은 1레벨로 말한다. 효과 크기는 1~5레벨 수열로 적는다.

## 11. 기준 데이터: 빌드가 기준

- 페이지는 언제나 **지금 빌드(origin/main 데이터)** 기준이다.
  - 변경 문서나 예전 원칙 문장이 데이터와 다르면 데이터를 따르고, 원칙 설명을 빌드에 맞춰 고친다.
- 시안을 만들거나 다시 올리기 전에 `git fetch` 후 마지막 반영 커밋 이후의 diff를 확인한다.
  - 바뀐 기술이 **다른 영웅 페이지의 비교표·본문·운용 예시**에 나오는지도 전수로 찾는다.
- main과 test가 갈라져 있으면 공개판은 main 기준이다. 차이는 제작자에게 알린다.
  - 예: 2026-11-05 결투가 11월 3일 패치는 main에만 있었다.
- 제작자가 새로 알려 준 이유는 페이지에만 쓰지 않는다. 저장소에도 기록한다(데이터 `//` 주석, `design/changes/<영웅>.md`, `design/workshop/intents/*.json`).

## 12. 이미지·업로드 기술 규칙

- 설명란은 8,000바이트 미만이다(UTF-8 바이트에 줄바꿈 하나당 1을 더한다). 현재 페이지는 이미지 주소를 포함해 3,400~4,600바이트다.
- 미리보기는 1MB 미만 PNG다.
- **같은 이미지를 같은 자리에 다시 올리면 등록만 남고 파일이 사라져 404가 난다.**
  - 업로드 PNG에는 매 실행마다 다른 텍스트 조각(nonce)을 넣는다.
  - 업로드 뒤에는 설명란의 모든 이미지 주소가 열리는지 확인한다(`broken_images` 0).
- **스팀 공개 페이지를 반복해서 조회하지 않는다**(HTTP 429).
  - 공개 반영은 수십 초 늦을 수 있다. 업로드를 다 끝낸 뒤 비로그인 브라우저로 한 번씩만 확인한다.
  - 확인 항목: 제목, 구독 버튼, 이미지 깨짐 0, 파일 크기.
  - 429가 나면 바로 다시 요청하지 않고 쉬었다가 한 번 재시도한다.
- 이미지 렌더 엔진의 시트 머리 이름과 설명 본문 `@@<시트 파일>` 줄은 정확히 한 번씩 짝이 맞아야 한다.

## 13. 만드는 순서

1. **데이터 확인**: 11절.
2. **글 작성**
   - `content_<영웅>.py`: 시트 데이터, `why`·`intent`·`lore`·`history`·`compare`·`plays`
   - `desc_<영웅>_ko.txt`: 개괄, `[h2]`, `@@` 줄
3. **확인**
   - 렌더: `hero_engine.py content_<영웅>`. 시트와 예시 이미지는 직접 열어 본다.
   - `@@` 짝, `why` 누락, 금지어(—, 제작자, 요청, 지시, 바로잡, 실수, 처음에, 한때)
   - 인용 원문 대조, 설명란 조립 크기
4. **시안 올리기**(비공개): `upload_dlc_pages.py <영웅>`(이미지 보관 아이템) → `upload_dlc_text.py <영웅>`(설명·제목·표지). `broken_images` 0을 확인한다.
5. **제작자 검토**
6. **출시**
   - `build_refined.py --item <id> --out …/hero_build/<영웅> --ref main --package <영웅>`
   - `release_hero.py <영웅>`(내용·제목에서 '(시안)' 제거·공개 전환)
   - 비로그인 공개 페이지 1회 확인
   - 출시 목록에 넣고 다른 페이지의 '다른 영웅 보기'를 갱신한다
