- 대화 당시 답변 원문(그 뒤 데이터가 바뀌었을 수 있음). 질문 원문:

메모장으로 고치고, 변경 항목을 적고, GitHub Desktop으로 커밋하는 순서입니다. 성녀 심판 명중을 85에서 90으로 올린다는 **가상의 예시**로 설명합니다(추천이 아닙니다).

## 0. 처음 한 번만: GitHub Desktop에 연결

1. GitHub Desktop을 실행합니다.
2. **File → Add local repository**를 누르고 아래 경로를 넣습니다.
   `C:\Program Files (x86)\Steam\steamapps\common\DarkestDungeon\mods\Rebalance`
3. 왼쪽 위 Current repository가 **Rebalance**면 연결된 겁니다. History 탭에서 지금까지의 커밋 기록이 보입니다.
4. "Publish repository" 버튼이 보여도 누르지 않아도 됩니다. 기록은 PC에만 저장됩니다. 포트폴리오로 GitHub에 올리는 건 나중에 정하면 됩니다.

## 1. 수치 고치기 (메모장)

1. 바닐라 수치를 봅니다: `mods\Rebalance\heroes\vestal\vestal.vanilla.txt`
2. 수정할 파일을 엽니다: `mods\Rebalance\heroes\vestal\vestal.info.darkest`
3. 해당 줄을 레벨 1~5 전부 고칩니다.
   ```
   combat_skill: .id "judgement" .level 0 ... .atk 90% ...
   ...
   combat_skill: .id "judgement" .level 4 ... .atk 110% ...
   ```
4. 그 기술의 마지막 줄 바로 밑에 주석 한 줄을 넣습니다. **영문과 숫자만** 쓰세요.
   ```
   // VES-001 judgement acc 85 -> 90 (all levels)
   ```
5. 저장합니다(Ctrl+S). 인코딩은 **UTF-8**로 둡니다(BOM 포함은 선택하지 않기).

- 항목 ID는 영웅 약어와 번호입니다. 약어표는 `design\README.md`에 있습니다(성녀 VES, 광대 JES, 중보병 MAA …).
- 기술 **효과 수치**(기절 확률, 회복량 등)는 영웅 파일이 아니라 효과 파일에 있습니다. 효과를 바꾸려면 저에게 요청하세요. 방패 파괴자 때처럼 새 효과 파일로 만들어 드립니다.
- 저장할 때 "액세스 거부"가 뜨면 메모장을 관리자 권한으로 실행하세요.

## 2. 변경 항목 적기

`mods\Rebalance\design\changes\vestal.md`를 메모장으로 열고 맨 아래에 추가합니다. 한글로 자유롭게 써도 됩니다.

```
### VES-001 심판 명중 85 → 90
- 상태: 적용
- 분류: 신규규칙
- 목표: G-02
- 의도: 원거리 기술인데 근접 기본 명중(85)이라 영웅 던전에서 체감이 급락함
- 근거: analysis/low_accuracy_skills.md — 원거리 기본 명중 90, 영웅 던전 명중률 82.5% → 87.5%
- 따르는 원칙: R-SKILL-01 (+5/레벨 유지)
- 어기는 원칙: 없음
- 영향: 성녀 딜 소폭 상승
- 검증: (플레이 후 기록)
```

- 급하면 **제목, 목표, 의도, 근거**만 적어도 됩니다. 나머지는 일관성 점검 때 제가 채웁니다.
- 해보고 접은 안은 지우지 말고 `상태: 기각`과 이유를 남깁니다. 포트폴리오에서 판단 과정을 보여주는 기록이 됩니다.

## 3. 게임에서 확인

1. 게임을 완전히 끄고 다시 켭니다.
2. 모드 목록에서 Rebalance가 켜져 있는지 봅니다.
3. 해당 기술 툴팁의 수치가 바뀌었는지 확인합니다.
4. 결과는 항목의 `검증:` 줄에 적습니다. 예: `2026-09-15 툴팁 90 확인, 영웅 던전 3판 체감 …`

## 4. 커밋 (GitHub Desktop)

1. 왼쪽 **Changes** 탭에 바뀐 파일 두 개가 보입니다: `vestal.info.darkest`, `changes/vestal.md`
2. 파일을 눌러 오른쪽 diff를 확인합니다. 빨간 줄이 이전 값, 초록 줄이 새 값입니다. 의도하지 않은 변경이 없는지 봅니다.
3. 커밋에 넣을 파일만 체크합니다. 같은 항목의 데이터와 문서를 한 커밋에 넣는 게 원칙입니다.
4. 왼쪽 아래 입력칸을 채웁니다.
   - **Summary**: `VES-001 성녀 심판 명중 85 → 90`
   - **Description**: `원거리 기본 명중에 맞춤. 근거: low_accuracy_skills.md` (한두 줄)
5. **Commit to main**을 누릅니다.

**커밋 단위:** 항목 하나당 커밋 하나가 가장 좋습니다. 같은 이유로 여러 기술을 함께 바꿨다면 `VES-001~003`처럼 묶어도 됩니다.

## 되돌리고 싶을 때

| 상황 | 방법 |
|---|---|
| 커밋 전, 파일 수정을 취소 | Changes 탭에서 파일 우클릭 → **Discard changes** |
| 이미 커밋한 변경을 취소 | History 탭에서 커밋 우클릭 → **Revert changes in commit** (기록은 남고 되돌리는 커밋이 새로 생김) |
| 바닐라 값 확인 | `.vanilla.txt` 또는 History의 첫 커밋 "바닐라 기준점" |

- 되돌렸으면 해당 항목의 상태를 `기각`으로 바꾸고 이유를 적어 **다음 커밋**에 포함하세요.

## 새 파일을 모드에 추가했을 때만

효과 파일 같은 새 파일을 추가했다면 파일 목록을 다시 만들어야 합니다. GitHub Desktop에서 **Repository → Open in Command Prompt**를 열고 실행하세요.

```bash
python tools/make_modfiles.py
```

기존 파일 수치만 고친 경우에는 필요 없습니다.

직접 하기 번거로우면 수정만 해 두고 "VES-001 커밋해줘"라고 말씀하셔도 됩니다. 제가 diff를 확인하고, 항목 문서를 채우고, 같은 형식으로 커밋합니다.
