- 대화 당시 답변 원문(그 뒤 데이터가 바뀌었을 수 있음). 질문 원문:

> 응 나의 목적은 모딩 파일을 배포하는 건데 영웅 리워크 및 밸런스조정을 합리적인 근거를 토대로 한 걸 배포하는 거야 그래서 로그가 전부 다 남아야 하고 의도와 근거도 전부 남아야 해 그걸 나중에 너가 취합하고 종합해서 근거와 이유를 전부 따져서 서로 충돌하는 부분도 찾아낼 수 있어야 해 그런 측면에서 지금 작업 방법이 잘 맞는지 확인해줘 다른 방법 알려줘도 괜찮아. 그래서 일단 내 생각과 입맛대로 전부 조정할거고 그거 토대로 너한테 일관성 체크해서 안 맞는 부분 정렬 시킨다음에 그걸 올릴 생각이야. 창작마당에 올릴거라 창작마당 형식도 확인해보고 어떻게 올리는 게 좋을지 어떻게 미리 정리하면 좋을지 파악해줘

지금 방식으로는 부족합니다. 수정 기록 이력이 남지 않고, 근거가 자유 서술이라 충돌을 찾기 어렵고, 업로드 폴더에 들어가면 안 되는 파일도 섞입니다. 창작마당 형식과 업로드 방식은 게임 폴더의 업로더 도움말과 구독 중인 모드 14개로 확인했습니다.

## 1. 지금 방식의 문제

| 필요한 것 | 지금 방식 | 문제 |
|---|---|---|
| 로그 전부 | `changelog.md`에 최종 상태만 기록 | 5-10을 나중에 5-11로 또 바꾸면 이전 값과 이전 의도가 사라짐 |
| 의도와 근거 | 번호별 자유 서술 | 사람은 읽기 좋지만 제가 항목끼리 비교하기 어려움 |
| 충돌 찾기 | 원칙이 따로 정리돼 있지 않음 | "이 수정이 어떤 원칙을 따르고 어떤 원칙과 부딪히는지"를 확인할 기준이 없음 |
| 배포 | 수정 폴더 = 업로드 폴더 | 기본 업로드 방식은 폴더 안 모든 파일을 올림 (실제로 한 모드는 업로더 로그까지 올라가 있음). 설계 문서, 바꾸지 않은 영웅 18명 복사본까지 배포됨 |

바꾸지 않은 복사본 18개가 배포되면, 우리가 바꾸지도 않은 영웅의 다른 모드와 쓸데없이 충돌합니다.

## 2. 추천 구조

**로그: git으로 남기기**
- 이 PC에 git 2.55와 **GitHub Desktop**이 이미 설치돼 있습니다.
- 메모장으로 고친 뒤 GitHub Desktop에서 바뀐 줄을 확인하고, 커밋 메시지에 항목 번호와 의도를 적습니다.
- 모든 수정 이력이 자동으로 남고, 제가 나중에 전체 이력을 읽을 수 있습니다.

**근거: 세 종류의 문서로 나누기**
```
mods/Rebalance/
  heroes/...                  ← 게임 데이터 (메모장 수정)
  design/
    rules.md                  ← 원칙서: 규칙마다 ID
    changes/man_at_arms.md    ← 영웅별 변경 항목
    rejected.md               ← 기각·보류한 안과 이유 (예: 중보병 속도 3→4 보류)
    playtest.md               ← 플레이 검증 기록
  tools/                      ← 점검·빌드 스크립트 (제가 작성)
```
기각한 안까지 남겨야 "왜 이렇게 안 했는지"도 나중에 따질 수 있습니다.

**원칙서 항목 예시**
```
## R-GROW-01 장비 피해 성장률
- 내용: 매혹 시 1열이면 최대 피해 15%, 헤비이면서 매혹 시 1열이면 최소 피해 15%, 그 외 20%
- 출처: 원본 분석 (기본 영웅 15명 전원 일치)
- 알려진 예외: 결투가 최소 피해 15% (반격으로 설명)
```

**변경 항목 예시**
```
### MAA-001 중보병 무기 기본 피해 5-9 → 5-10
- 상태: 적용
- 의도: 지원형 헤비의 피해를, 지원 기술의 대가를 반영한 정상 범위로 올림
- 근거: 체력–피해 추세 −1.75(최하), 지원 기술 반영 후에도 −1.07
- 따르는 원칙: R-GROW-01, R-PRESET-01
- 어기는 원칙: 없음
- 영향: 응징 반격 피해도 함께 +9%
```
- 사용자는 **의도와 근거만** 적으면 됩니다. 원본값과 변경값은 제가 원본과 비교해서 채웁니다.
- 데이터 파일의 주석은 `// MAA-001`처럼 항목 ID만 남깁니다.
- 지금 있는 #1 항목은 이 형식으로 옮기겠습니다.

**점검할 때 제가 찾아내는 것**
- **누락:** 데이터는 바뀌었는데 항목이 없는 경우, 또는 그 반대
- **원칙 위반:** 성장 공식이나 기본값 규칙을 어겼는데 "어기는 원칙"에 적지 않은 경우
- **원칙끼리 충돌:** 예를 들어 "반격이 있으면 15%" 규칙과 "매혹 시 1열" 규칙이 결투가에서 다른 값을 요구하는 경우
- **근거가 낡은 경우:** 다른 수정이 먼저 체력을 바꿔서 MAA-001의 추세선 근거가 더는 맞지 않는 경우
- **의도 충돌:** 같은 능력치를 서로 다른 이유로 반대 방향으로 민 경우

## 3. 창작마당 형식 (업로더 도움말 기준)

| 항목 | 내용 |
|---|---|
| 업로드 방법 | `_windows/steam_workshop_upload.exe`에 `project.xml`을 끌어다 놓기. Steam 로그인 필요 |
| 첫 업로드 | 창작마당 항목이 새로 만들어지고 `project.xml`에 `PublishedFileId`가 기록됨. 이후 업데이트에도 같은 파일을 계속 써야 하니 git에 보관 |
| `Title` | 모드 이름 |
| `ItemDescriptionShort` | 512자 이하. 게임 모드 목록에서 마우스를 올리면 보이는 설명 |
| `ItemDescription` | 8000자 이하. Steam 창작마당 페이지 본문 (BBCode 사용: `[b]`, `[list]`, `[img]`) |
| `UpdateDetails` | 업데이트마다 쓰는 변경 내역. 창작마당의 "변경 사항" 탭에 쌓임 |
| 버전 | `VersionMajor`/`VersionMinor`. 게임 안에서 "Rebalance (0.1)"처럼 표시됨 |
| 공개 범위 | `private`(나만) → `friends`(친구, 테스트용) → `public`(전체) |
| 미리보기 이미지 | `preview_icon.png`, 1MB 미만. 구독 모드 대부분이 512×512 |
| 태그 | 자유 입력. 영웅 수정 모드는 보통 `Class Tweaks` |
| 자동 생성 | 업로더가 `modfiles.txt`와 현지화 파일(`.loc2`)을 만들어 줌. `dont_submit` 모드는 올리지 않고 이 두 가지만 생성 |
| 업로드 방식 | `direct_upload`: 폴더 전체 업로드<br>`strip_and_upload`: 원본과 같은 파일을 빼고 업로드 |

- **`strip_and_upload`는 수정 폴더에 직접 쓰지 마세요.** 업로더 문자열에 "Removing unchanged file"이 있어서, 원본과 같은 파일을 폴더에서 실제로 지울 가능성이 있습니다.
- **기술 이름이나 설명을 바꾸면** `localization/*.string_table.xml`에 영어와 한국어 항목을 넣어야 합니다. 업로더가 이를 `.loc2`로 컴파일합니다. 수치만 바꾸는 경우엔 툴팁이 데이터를 따라가서 필요 없습니다.
- **참고할 선례:** 구독 중인 "DD Tweaks 1.0 - Musketeer"가 가장 비슷한 모드입니다.
  - 모드 안에 `changes.txt`를 넣고 "레벨 1~5 × 원본 대비 변경" 표와 설계 이유를 적었습니다.
  - 창작마당 설명에는 설계 목표, 영웅별 역할, 세이브 호환성, 충돌하는 모드를 적었습니다.
- **세이브 호환성:** 수치 변경은 기존 세이브에서도 안전합니다. 기술 ID를 바꾸거나 없애면 기존 영웅이 깨지므로, 이것도 원칙서에 규칙으로 넣어 두는 게 좋습니다.

## 4. 전체 흐름

1. **자유 조정:** 메모장으로 수정하고, 변경 항목에 의도와 근거를 적고, GitHub Desktop으로 커밋합니다.
2. **일관성 점검:** 제가 원본 비교, 항목 대조, 원칙 위반, 항목 간 충돌을 담은 보고서를 만듭니다.
3. **정렬:** 보고서를 보고 수치나 원칙을 고치고 커밋합니다.
4. **배포 빌드:** 스크립트가 게임 폴더 밖에 깨끗한 업로드 폴더를 만듭니다.
   - 넣는 것: 원본과 다른 파일, `project.xml`, 미리보기 이미지
   - 자동으로 만드는 것: `changes.txt`(영어/한국어 표), 창작마당 설명, 이번 버전 변경 내역
5. **업로드:** 비공개로 먼저 올려서 구독 테스트를 한 뒤 공개로 바꿉니다.

**아직 게임에서 확인하지 않은 것**
- 게임이 `mods/Rebalance` 안의 `design/`, `.git` 같은 추가 폴더를 무시하는지
- 영웅 파일의 `//` 주석이 문제없이 읽히는지

게임 파일에 `modfiles.txt`를 읽는 코드가 있어서 목록에 없는 파일은 무시될 가능성이 높지만, 첫 테스트 때 같이 확인하겠습니다.
