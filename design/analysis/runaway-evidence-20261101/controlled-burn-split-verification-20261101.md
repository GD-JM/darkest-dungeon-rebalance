# 통제된 화상 이동/턴 시작 분리 조사

요청: 게임 미적용, 최초 화상은2/2/3/3/4를 다음 검토 기준으로 사용. 실제 데이터와 실행파일을 조사했다.

## 확인
- 설치된win64 Darkest.exe와분석사본 SHA256 동일:4d78fbfaa65b7d002d2208d02da809200f4a5723119521180e30100d6f1a75f2.
- 기존GhidraDB를readOnly/noanalysis로열어 FUN_14059c180,14059c340,14059bcb0을 새로 디컴파일. 결과 burn-trigger-split-check.c 및.log. 원본프로그램변경discard 로그 확인. 함수 산술을 Capstone 어셈블리로 추가대조.
- 설치효과데이터의 관련필드는.controlled_burn_amount/.controlled_burn_duration. 실행파일문자열 및효과로더 FUN_1404e6c00도 이두입력만확인. amount는효과객체+0x2c0,duration은+0x2c4.
- 생성FUN_14059bcb0이0x18바이트영역항목을만들며 같은amount를entry+4에저장. duration은+8,영역rank비트마스크는+0.
- 턴시작 FUN_14059c180: 현재점유열과불영역의교집합비트수×entry[1]를FUN_1405ba4d0(화상량추가)에전달.
- 이동 FUN_14059c340: 이전/새점유열과몸크기로이동경로마스크를구성하고기존점유열제외. 교차한각영역의entry[1]를같은화상추가함수에전달. 별도이동배율/이동전용화상량을읽지않음.
- 엔진내로그문자열로분기명교차확인: '[CB] TICK ... triggers=%d burn=%d', '[CB] MOVE-BURN ... check=0x%X ... stacks=%d'. 따라서 단순히 함수이름으로역할을추측한것이아님.
- 대형적은턴시작에겹치는불붙은열수만큼증가가능. 이동은이전위치에서벗어나새로지나거나진입한영역판정이며모든이동이무조건발동하는것은아님.

## 결론과범위
기존통제된화상의데이터설정으로턴시작과이동화상량을독립조절할수없다. 단순필드추가로읽히는이동전용설정을찾지못했으며두분기가명백히동일한저장값을소비한다. 기존코드그대로amount를올리면둘다올라간다.

정확한이동전용상향은엔진분기수정/추가로직이필요하다. 코드분기가분리되어있다는것은수정지점이있다는뜻이지,현재창작마당데이터모드에서지원된다는뜻이아니다. 실제바이너리패치나런타임후킹은하지않았다.

특정당기기기술에추가화상을붙이는우회는적중/이동성공/불영역통과를동일하게판정하는것이아니며모든아군이동기연계를대체하지못한다. 모든가능한우회구현이불가능하다는일반증명은아니지만검증되지않은대안을가능하다고안내하지않는다.

최초화상22334는別.effect의.dotBurn이므로지면amount와독립조절가능. 현재최초6/지면2/2/3/3/4/지속3은변경하지않았다. 이번조사는정적엔진검증이며새게임전투실측은아니다.
