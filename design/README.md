# Rebalance 작업 안내

## 폴더

```
mods/Rebalance/
  heroes/<영웅>/<영웅>.info.darkest   ← 수정하는 파일 (게임이 읽음)
  heroes/<영웅>/<영웅>.vanilla.txt    ← 바닐라 참고 시트 (게임이 안 읽음, 배포 제외)
  heroes/<영웅>/<영웅>.effects_edit.txt ← 효과 수치 편집용 사본 (게임이 안 읽음, 정리 시 적용)
  design/
    intent.md        기획 의도·목표(G-xx)·수정 원칙(P-xx)
    rules.md         원본 수치 규칙(R-xx) + 원칙 이탈 목록
    analysis/        근거 자료 (회복 분석, DLC 패치 이력 …)
    changes/<영웅>.md 영웅별 변경 항목
    feedback.md      창작마당·플레이 테스트 피드백 기록 (FB-xxx)
    vanilla/         총사 바닐라 시트 (MUS-001로 편입)
  effects/rebalance_<영웅>.effects.darkest  ← 모드가 새 이름으로 추가한 효과 (바닐라 효과 파일은 덮어쓰지 않음)
  tools/make_modfiles.py   파일 목록(modfiles.txt) 다시 만들기
  tools/make_effect_edit_files.py   효과 편집용 사본 만들기
  tools/apply_effect_edits.py       편집용 사본의 변경을 게임 데이터에 적용
  project.xml / preview_icon.png   모드 목록·창작마당 정보
```

## 간편 방식 (기본) [사용자]

1. `heroes/<영웅>/<영웅>.info.darkest`를 메모장으로 고친다.
2. 바꾼 줄 밑에 `//`로 시작하는 줄을 여러 줄 써도 된다. 의도·근거·생각을 한국어 자연어로 자유롭게 적는다.
3. Claude에게 "정리해줘"라고 요청한다. Claude가 하는 일:
   - 마지막 커밋과 비교해 바뀐 수치를 추출한다.
   - 자연어 메모를 **원문 그대로** `design/changes/<영웅>.md`의 새 항목(ID 부여)에 옮기고 나머지 칸을 채운다.
   - 데이터 파일의 사용자 원문 메모는 보존하고, `// <ID> 영문 변경·의도 요약` 주석을 추가한다.
   - 커밋한다.

**기본 규칙: 바꾼 줄 밑에는 반드시 `//` 주석을 단다.** 영웅 파일과 효과 편집 사본 모두 해당한다.
- 영웅 파일에서 연속으로 바뀐 줄(예: 한 기술의 1~5레벨)은 그 묶음 밑에 주석 하나로 충분하다.
- 효과 편집 사본은 효과 줄마다 바로 밑에 주석을 단다.
- 검사: `python tools/check_comments.py`. 원본과 다른데 주석이 없는 줄을 모두 보여 준다. "정리" 때 Claude가 항상 실행한다.
- 로그 세 층
  - 데이터 파일의 `// ID 요약`: 무엇을 바꿨나
  - `design/changes`: 왜 바꿨나, 사용자 메모 원문
  - git 커밋: 언제 바꿨나

주의
- `//` 줄은 줄 맨 앞에서 시작한다. 수치 줄 끝에 이어 쓰지 않는다.
- 한글 주석이 든 상태로 게임이 정상 로드되는지는 아직 검증 전이다. 게임 테스트 전에 정리를 먼저 요청하는 것을 권장한다.

## 효과 수치 편집 (기절 확률, 출혈량, 버프 수치 등)

기술의 효과 수치는 영웅 파일이 아니라 효과 파일에 있다. 원본 효과 파일은 다른 영웅·몬스터와 공유되므로 통째로 복사해 덮어쓰지 않는다.

1. `heroes/<영웅>/<영웅>.effects_edit.txt`를 메모장으로 연다. 그 영웅 기술이 쓰는 효과 줄만 기술별로 모아 둔 **편집용 사본**이다. **게임은 이 파일을 읽지 않는다.**
2. 수치만 고친다. 효과 줄을 지우거나 이름을 바꾸지 않는다. 메모는 바꾼 줄 바로 밑에 `//`로 쓴다. `//#` 줄은 자동 설명이다.
3. Claude에게 "정리해줘"라고 요청한다. 내부적으로 `python tools/apply_effect_edits.py`가 실행된다.
   - 원본과 달라진 효과만 새 이름(`RB <약어> 원래이름`)으로 `effects/rebalance_<영웅>.effects.darkest`에 들어간다.
   - 그 영웅 기술 줄이 새 효과를 가리키게 바뀐다. 다른 영웅·몬스터는 영향이 없다.
   - 괴인의 `.human_effects`와 `.beast_effects`도 함께 처리한다. 편집 사본에는 변신·복귀의 두 목록이 모두 포함된다.
   - 원래 값으로 되돌리면 새 효과가 사라지고 참조도 원래대로 돌아간다.
4. 이후 기록·커밋은 간편 방식과 같다.

### 새 효과 만들기 (원본에 없는 효과)

예: 현상금 사냥꾼 출혈 대상 추가 피해(BH-001).

1. 편집 사본 맨 아래 "모드 신규 효과" 구역에 `effect:` 줄을 추가한다. 이름은 반드시 `RB <약어> `로 시작한다(예: `"RB BH Bleed Killer 1"`). 비슷한 원본 효과 줄을 복사해 이름과 수치만 바꾸면 된다.
2. 줄 바로 밑 메모
   - `// 영문 한 줄`: 게임용 효과 파일에도 복사된다.
   - `//` 한국어 메모: 편집 사본에만 남고, 정리 때 `design/changes`로 옮겨진다.
3. 영웅 `.info.darkest`의 기술 줄 `.effect` 목록에 그 이름을 따옴표로 추가한다.
4. "정리해줘" → 도구가 확인한다.
   - 기술이 참조하는데 사본에 없는 신규 효과 → 오류
   - 사본에 있는데 기술이 안 쓰는 신규 효과 → 경고

주의: 메모장에 파일을 열어 둔 채 Claude가 같은 파일을 고치면, 메모장에서 저장할 때 Claude의 수정이 사라진다. Claude에게 정리를 요청하기 전에 저장하고, 정리 후에는 파일을 다시 연다.

- 사본 다시 만들기(편집 내용이 사라지므로 주의): `python tools/make_effect_edit_files.py --force <영웅>`
- 강화 효과(`.buff_ids`)의 실제 수치는 JSON에 있어 사본에서는 참고만 가능하다. 바꾸려면 요청한다.

## 수정 절차 (직접 할 때)

1. `heroes/<영웅>/<영웅>.info.darkest`를 메모장으로 고친다. 바닐라 수치는 같은 폴더의 `.vanilla.txt`에서 본다.
2. 바꾼 줄 바로 밑에 `// <항목 ID>` 한 줄을 넣는다. 예: `// MAA-002`
3. `design/changes/<영웅>.md`에 항목을 추가한다.
   - 최소한 **제목, 목표, 의도, 근거**만 적으면 된다. 원본값·변경값·원칙 대조는 점검 때 채운다.
   - 해보고 접은 안도 지우지 말고 `상태: 기각`으로 남긴다.
4. GitHub Desktop에서 커밋한다. 커밋 메시지 첫 줄에 항목 ID를 넣는다. 예: `MAA-002 응징 피해 보정 조정`
5. 새 파일(효과 파일 등)을 모드에 추가했으면 `python tools/make_modfiles.py`를 실행하거나 Claude에게 요청한다.

- 기술 효과 수치(기절 확률, 출혈량 등)는 영웅 파일이 아니라 효과 파일에 있다. 원본 효과 파일은 복사하지 말고 `heroes/<영웅>/<영웅>.effects_edit.txt`에서 고친다(위 "효과 수치 편집").
- 기술 ID(`.id "..."`)는 바꾸거나 지우지 않는다(P-04, 세이브 호환).

## 2026-10-05 주석·의도 기록 강화 (사용자 요청)

수정 데이터에는 `// 변경 ID + 변경 설명/의도 요약`을 반드시 남긴다. 영웅 기술의 연속 레벨은 묶음 아래 한 주석을 공유할 수 있지만, 효과 편집 사본과 게임용 파생 효과는 바뀐 효과 **한 줄마다 바로 아래** 주석이 필요하다. `//#` 자동 설명이나 기술 구역 끝의 주석 하나는 효과별 주석을 대신하지 않는다. 원본 대비 RB 효과 참조 변경도 추적한다.

`design/changes/<영웅>.md`에는 원본/현재 값, 의도, 근거, 원문 메모, 이력을 연결한다. 이미 쓴 사용자 한국어 주석은 지우거나 바꿔 쓰지 않고 원문 그대로 보존한다. 옛 주석과 최신 데이터가 다르면 현재 추적 주석과 날짜별 기록으로 구분한다. 의도를 확인할 근거가 없으면 미확인으로 적고, 사후 이유를 만들지 않는다.

주석 정리는 수치 수정 승인이 아니다. 편집 사본과 설치 데이터가 다르면 각각 기록하고 전역 효과 적용을 자동 실행하지 않는다. 검사 `python tools/check_comments.py`는 효과 행별 주석·ID·설명·문서 연결과 게임용 파생 효과까지 확인하고, 위반 시 종료 코드1을 반환한다. 기존 자연어 메모만 있는 작업 중 파일은 의도 ID 주석을 덧붙여 보존한다.


## 총사 편집 (MUS-001)

총사는 설치된 YAMR을 전체 편입했다. heroes/musketeer의 info/vanilla/effects_edit 파일을 다른 영웅처럼 사용한다. 바닐라 시트는 실제 바닐라이며, 고정 YAMR 비교 원본은 design/imports/musketeer에 있다. 효과 정리는 외부 개조 효과도 원본으로 인식한다. 반격/재충전/장신구 추가 효과의 참조도 함께 갱신하고 되돌릴 수 있다. 적용은 tools/apply_effect_edits.py musketeer, 주석 확인은 tools/check_comments.py musketeer. 기존 편집 사본은 --force로 덮어쓰지 않는다.

독립 통합본을 쓸 때 기존 YAMR·다른 총사 리워크·Trinket Separator·Trinkets Plus를 끄고 Rebalance를 우선 적용한다. 총사 DLC 등 게임 제공 자원은 계속 사용한다. JSON/이미지/번역 바이너리의 // 의도 기록은 design/imports/musketeer/intents.txt에 있으며 JSON 안에 불법 주석을 넣지 않는다. 새 밸런스 후보는 이 편입에 포함되지 않았다.
